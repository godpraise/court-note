# 완료 처리 후속 개선 — 2026-11-16

현재 로컬 브랜치의 미배포 개선이다. 이번 변경·테스트 코드는 Codex의 도움으로 작성했다. 이를 사용자가 과거에 독립 작성한 코드로 주장하지 않는다. 실제 배포본·원본 ZIP은 보존한다.

## 변경과 근거

기존 완료 경로는 레슨 상태와 각 수강권을 따로 저장했다. 최신 데이터 대신 화면 상태를 사용해 반복 요청 시 중복 차감할 수 있었다. `lesson-completion.js`는 Firestore 트랜잭션에서 레슨·수강권을 모두 읽은 뒤 함께 쓴다. 완료 상태이면 쓰기 없이 반환한다. 잘못된 참가자, 누락·비활성·소진 수강권은 전체 작업을 실패시킨다. 기존 마지막 회차의 정산 분기는 유지한다.

화면의 진행 중 표시도 같은 레슨의 중복 요청을 줄인다. 데이터 일관성의 근거는 이 표시가 아니라 트랜잭션이다. 서로 다른 레슨이 같은 수강권을 동시에 사용해도 최신 사용 횟수로 재시도한다. 서비스 워커에 새 모듈을 포함했다.

## 재현

Node와 Java 21 이상이 설치된 환경에서 저장소 루트에서 실행한다.

```sh
npm ci
npm test
npm run test:rules
```

로컬 전용 `demo-court-note-isolation`, `127.0.0.1:8787`에서 실제 Firestore 규칙 엔진을 사용한다. 운영 데이터와 AI API를 호출하지 않는다.

- 단위 테스트 11개: 기존 세션·API 인증·입력 검증.
- 접근 규칙 7개: 기존 코치 격리·공통 자료 접근 차단.
- 완료 트랜잭션 10개: 반복, 동일 레슨 8개 동시 요청, 다른 레슨 2개 동시 차감, 그룹 수강권·정산, 누락 시 롤백, 소진·비활성, 취소 상태, 결석, 중복 참가자, 다른 코치 접근 거부.
- 관찰 결과: 총 28개 통과. 동일 레슨은 완료·차감 1회, 서로 다른 수업 2개는 차감 2회. 이는 로컬 테스트 결과다.

## 남은 범위

앱의 완료 함수 경로를 검증한 것이며, 소유자가 자신의 Firestore 문서를 직접 변조하는 모든 경우를 막는 서버 전용 업무 로직은 아니다. 완료 후 편집·취소의 역정산, 기존 중복 차감 복구, 실제 이메일 로그인·AI 응답·기기 간 캐시·운영 배포는 별도 확인한다. 실제 코치 업무 시간·오류 감소율을 측정하지 않았다.
