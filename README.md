# 코트노트 (Court Note)

피클볼 코치의 예약·회원·레슨 기록·수강권·정산을 연결하는 PWA 웹앱입니다.

## 작업 범위

- 개발 기간: 2026.08~2026.09 (기존 이력서와 사용자 회고 기준)
- 지인의 아이디어를 바탕으로 상세 기획·설계, AI 활용 구현, 예외 검토·수정과 배포를 수행했습니다.
- 사용자 확인: 직접 코드를 편집하기보다 문제를 설명해 AI에 수정을 요청하고 실행 결과로 동작을 확인했습니다. 독립 작성 코드의 비율을 주장하지 않습니다.
- 최초 배포본은 본인·지인의 공유형 테스트였습니다. 코치별 데이터 분리는 기획 단계였으며, 2026-11-13 후속 개선에서 로컬 구현·검증했습니다.

## 기술과 파일

- `index.html`: Vanilla JavaScript 화면과 업무 상태 처리, Firestore 연동
- `api/clean-note.js`: Firebase ID 토큰과 입력을 확인한 뒤 Anthropic API에 메모 정리를 요청하는 Vercel 서버 함수
- `coach-session.js`: 로그인 UID별 Firestore 경로, 구독 해제와 계정 전환 상태 관리
- `lesson-completion.js`: 최신 레슨·수강권을 읽어 함께 저장하는 완료 트랜잭션
- `firestore.rules`: 등록된 코치의 본인 데이터만 허용하는 Firestore 규칙
- `manifest.json`, `sw.js`, `icons/`: PWA 구성

AI 요청 키와 서비스 계정 정보는 서버 환경변수로 관리합니다. AI API는 토큰의 유효성·이메일 인증과 등록된 코치인지도 확인합니다.

## 코치별 데이터 분리

데이터는 `coaches/{Firebase Auth UID}/{collection}/{document}`에 저장합니다. 회원·레슨·수강권·일지·장소·커리큘럼·진도를 분리하며, Firestore 규칙이 다른 UID의 조회·추가·수정·삭제를 거부합니다. `admins/{로그인 이메일}`에 등록된 인증된 코치만 사용할 수 있고, 클라이언트는 이 접근 목록을 변경할 수 없습니다.

기존 공통 컬렉션의 테스트 자료는 삭제하거나 자동 이전하지 않습니다. 새 코치는 빈 데이터로 시작하며, 공통 테스트 자료는 새 규칙에서 클라이언트 접근을 차단합니다. 로그아웃과 계정 전환 시 기존 구독·화면 상태를 정리합니다.

**현재는 로컬 수정·검증 단계이며 실서비스에 배포하지 않았습니다.** 동작을 실제 서비스에 반영하려면 새 앱 코드·서버 함수와 `firestore.rules`를 함께 적용해야 합니다. 자세한 절차와 검증 범위는 [코치별 분리 안내](docs/coach-isolation.md)를 참고하세요.

## 실행 준비

1. `npm ci`로 lock 파일에 고정된 의존성을 설치합니다.
2. `index.html`의 Firebase 설정이 사용할 프로젝트와 맞는지 확인합니다. 별도 프로젝트용 설정은 `examples/firebase-config.example.js`의 `YOUR_FIREBASE_*` 값을 참고합니다.
3. `.env.example`의 변수 이름을 참고해 자신의 서버 환경변수를 설정합니다. 실제 `.env`나 서비스 계정 JSON은 Git에 추가하지 않습니다.
4. 정적 화면과 `/api/clean-note` 서버 경로를 함께 제공하는 환경이 필요합니다. 단순 파일 열기나 정적 HTTP 서버만으로 AI API까지 실행되지는 않습니다. 배포는 자신의 Vercel/Firebase 설정을 별도로 확인한 뒤 진행합니다.

## 현재 결과와 한계

초기 공유형 앱을 구현·배포했고, 지인 대상 테스트에서 긍정적인 초기 반응이 있었다는 사용자 회고가 있습니다. 동생 대상 테스트는 별도 프로젝트인 찍히면 아웃입니다. 실제 코치 업무 시간·매출·장기 사용 지표는 없습니다. 과거 정리 문서의 1분 확인·3분 저장은 AI가 정리하면서 추가한 수치로 사용자가 확인했으므로 프로젝트 목표·성과에서 삭제했습니다.

2026-11-12 공유형 보존 코드에서는 같은 레슨을 다시 완료하면 수강권 사용 횟수가 1에서 2로 증가하는 동작이 확인됐습니다. 2026-11-16 후속 개선에서 완료 상태와 수강권 차감을 하나의 트랜잭션으로 묶었습니다. 이미 완료된 레슨은 다시 차감하지 않으며, 수강권 누락·소진 등 오류 시 전체 저장을 중단합니다. 로컬 단위 11개·접근 규칙 7개·완료 트랜잭션 10개, 총 28개 테스트를 통과했습니다. **신규 코드와 규칙은 미배포이며, 실제 사용자 성과나 운영 환경 검증이 아닙니다.** 자세한 재현 방법과 제한은 [완료 처리 검증](docs/lesson-completion.md)을 참고하세요.

2026-11-12에는 기존 `court-note` 저장소에 포트폴리오 문서를 통합했고, 2026-11-13에는 별도 로컬 브랜치에서 코치별 격리를 구현했습니다. `examples/index.template.html`은 당시 공유형의 보존 예시이므로 새 배포에는 사용하지 않습니다. 현재 앱은 루트의 `index.html`입니다. 원본·서비스 계정·기존 저장소 이력은 별도로 보존했습니다. 새 라이선스를 임의로 추가하지 않았습니다.
